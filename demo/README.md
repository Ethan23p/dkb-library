# dkb-demo — prebuilt knowledge bases

The second plugin in this repo's marketplace. It ships two knowledge bases that
are already built, so someone can install `dkb` and ask a real question about
real sources within a minute, instead of being handed an empty system and told
to assemble a corpus first.

Playtesters should read [`../docs/PLAYTESTING.md`](../docs/PLAYTESTING.md), not
this file. This one is for whoever maintains the demo.

## The corpora

| Name | What it is | Size | `explore-model` |
|---|---|---|---|
| `lhc` | Five papers on whether the LHC could produce a dangerous micro black hole — CERN's safety review, the astrophysical bounds, and Ord, Hillerbrand & Sandberg disputing the others' methodology. They disagree, on purpose. | ~74k words | `claude-sonnet-5` |
| `saber` | How American Airlines built SABRE in 1960 and put terminals in front of hourly reservation staff. | ~5k words | `claude-opus-5` |

`lhc` is the default because it is the more impressive demonstration; it runs on
Sonnet 5 because at ~187k tokens per question, every question is a real cost on
the playtester's own usage limit. `saber` is small enough that Opus 5 is
affordable, so it gets it. The model is a per-knowledge-base setting living in
each KB's own `config.yml` — see amendment A4 in
[`../docs/CONTRACTS.md`](../docs/CONTRACTS.md).

## Layout

```
demo/
  .claude-plugin/plugin.json   manifest (name: dkb-demo)
  bin/dkb-demo                 list · use · path
  skills/dkb-demo/SKILL.md     the playtest interface guide
  kbs/<name>/                  generated: config.yml, kb.sqlite, convention.md
  build.ts                     regenerates kbs/ from the fixture corpora
```

## Hydration, and why it exists

`dkb-demo use <name>` copies a knowledge base out of the plugin and into the
user's own directory (`./demo-<name>/` by default). It refuses to overwrite an
existing copy; `--force` overrides.

The copy is not a convenience — it is required. A plugin root is ephemeral:
Claude Code replaces it on every update and garbage-collects the old version
after about two weeks. A knowledge base left inside one would take the user's
corrections and additions with it when it went. See "Path resolution inside the
plugin" in [`../docs/PLUGIN.md`](../docs/PLUGIN.md).

Because hydration is a directory copy, it is instant and involves no inference,
no ingestion, and no Bun-side work. That is what makes "installed to a real
answer in a few minutes" true rather than aspirational.

## Rebuilding

```sh
bun demo/build.ts          # both corpora
bun demo/build.ts saber    # just one
```

The build initializes a fresh knowledge base per corpus, ingests every source by
driving the shipped CLI as a subprocess (so it exercises the real path, not a
private one), pins `explore-model`, and then re-derives each source's sha256
from the fixture on disk and compares it against the ledger. A mismatch fails
the build.

Sources are read **in place** from `testing/fixtures/corpus-lhc/` and
`testing/fixtures/corpus/` — the `.import.json` sidecars' `content_path`
resolves against their own directory, so nothing is duplicated into `demo/`. The
only generated bytes committed here are the two `kb.sqlite` files, which is why
`.gitattributes` marks `*.sqlite binary`.

Committing the built artifacts is deliberate: the demo has to work without a
build step, and a reproducible script beats a hand-forged binary nobody can
audit. Re-run the build and you get the same knowledge base from the same
sources.

**No generated prose ships here.** The ledgers contain only `kb/*` bookkeeping
and the `source/*` metadata from the sidecars — the same Source Data First rule
the system holds itself to at retrieval time.

## Changing the corpora

Edit the `CORPORA` array in `build.ts` (name, fixture directory, blurb, model),
then update `kb_blurb()` and `kb_stats()` in `bin/dkb-demo` — that function is
the single place the user-facing size and latency figures live, and they are
measured, not estimated. Re-measure if a corpus or its model changes. The
per-corpus descriptions in `skills/dkb-demo/SKILL.md` and
`docs/PLAYTESTING.md` need the same treatment.
